# AGENTS.md

## Overview

- This repo holds the openipdata.org data workers, workflows, builders, and the website service in `site/`.
- Workflows are being moved here from another repo step by step. This repo must stay self-contained: no imports, submodules, URLs, or file references to other repos. Reproduce anything needed here.

## Layout

- `site/`: standalone Go module (`package main`, binary `openipdata-site`): the openipdata.org website, one static binary behind nginx behind Cloudflare. It may share the worker VM (decided 2026-11-14), but stays fully separate: its own user, `/opt/openipdata-site`, `/var/lib/openipdata-site`, and its data only from the GitHub releases, never the worker's files under `/var/lib/openipdata`. It must not import `hatchet`, `mmdbbuilder` or `iplistener`; its only third-party dependencies are the MMDB reader and the SQLite driver `modernc.org/sqlite` (pure Go, the same version as the worker's, so the binary stays a static `CGO_ENABLED=0` build; a new dependency needs the owner's OK). Templates, CSS and the two font files are embedded (`go:embed`).
- `infra/`: VM provisioning (`init-hatchet-runner-vm.sh`), systemd unit, env template. No Go code. `infra/site/` holds the website VM setup (init script, updater, MMDB puller, Cloudflare range script, nginx files, systemd units; no Go code).
- `hatchet/`: Go module for `openipdata-worker`, the Hatchet worker. `main.go` registers workflows; each workflow lives in its own folder (`hatchet/asn/` for `build-asn-data`, `hatchet/pdb/` for `sync-peeringdb`, `hatchet/domains/` for `update-asn-domains`, `hatchet/geofeeds/` for `sync-geofeeds`, `hatchet/bgp/` for `sync-bgp`, `hatchet/geo/` for `build-geo-data`, `hatchet/rdns/` for `resolve-ips`, `hatchet/rdnsrules/` for `learn-rdns-rules` with its tasks `learn` and `propose-codes`, `hatchet/mlab/` for `import-mlab`). `hatchet/schema/` creates and upgrades the shared Postgres tables; `hatchet/publish/` uploads artifacts to R2 and GitHub releases (a file that is already there byte-for-byte is not sent again) and downloads the R2 layer files; `hatchet/rirstats/` parses RIR delegated-extended stats and splits address ranges into prefixes; `hatchet/download/` downloads a file unless the local copy is current (the caller passes the HTTP client); `hatchet/outputs/` prunes old output directories and has the small helpers `asn` and `geo` share (last log lines, file size); `hatchet/ipdata/` has what several workflows need about IP space and `public.asn` (public-address check, country-code check, announced prefixes of `public.asn.json`, the `seen_at` filter). Workflows share this code, never each other's downloaded files.
- `mmdbbuilder/`: Go module for `mmdbbuilder`, a standalone CLI (`package main`) with one subcommand per database (`asn`, `geo`), plus `eval` (scores a geo MMDB), `lookup` (reads one: a report, or with `-in`/`-out` the city of each IP of a file; a guess city is left out; `-with-source` adds a fourth column, the record's `city_source`, and `-countries` with it also writes IPs that have a country but no city, with an empty city; without the flags the output is byte-identical to before) and `gaps` (the IPv4 /24s of a geo MMDB with a country and no city (a city whose `city_source` is `80-asn-main`, `25-bgp` or `36-mlab` counts as none; the list is `noSampleSources` next to `isGuessSource`), as runs `<first /24> <count> <country>`; a /24 split between countries, or with a city in any part, is left out). `geo -asn-main <asn-prefixes.csv.gz>` adds the guessed ASN main city fill after all layers (see the ip2geo layers rule).
- `tools/llm-codes-test/`: scratch Python test (standard library only), not run by the worker: compares LLMs (through OpenRouter, key only in `OPENROUTER_TEST_API_KEY`) on proposing city codes for router-name domains. It sends router hop names only, never visitor names; its exports and answers are git-ignored.
- `tools/mapdata/`: standalone Go module (`package main`, standard library only, run by hand, not by the worker or the site build): turns the Natural Earth 1:50m country outlines (public domain GeoJSON, not in Git) into `site/static/world.bin`, the file the website draws its map from. Source, licence, input hash and the command are in `tools/mapdata/README.md`.
- `iplistener/`: standalone Go module (`package main`) plus install script, unit and env template; it runs on the web servers that serve visitors, not on the worker VM. It tails the nginx access log and upserts visitor IPs into `public.visitor_ips`. It must not import `hatchet` or `mmdbbuilder`; it reproduces small helpers (e.g. hiding the DSN in pgx errors).
- `beacon/`: standalone Go module (`package main`, binary `openipdata-beacon`, dependencies: `golang-dnstap`, `miekg/dns`, `go-redis`, `protobuf`) for the web VM. Knot DNS serves the zone `r.openipdata.org` and sends each query through dnstap to a unix socket; the daemon stores the address of the resolver that asked for `<32 hex>.r.openipdata.org` in Redis (contract in the "Server" bullet). It must not import `hatchet`, `mmdbbuilder`, `site` or `iplistener`.
- No `go.mod` or Go code at the repo root. Each module builds on its own.
- `hatchet` must not import `mmdbbuilder`; it runs the `mmdbbuilder` binary (and, for `resolve-ips`, `scamper`) found next to its own executable.

## Website decisions (2026-11-14)

- Stack: Go only. `net/http` plus `html/template` parsed once at start; no Node, npm, Astro, client framework, CSS tool or other build step. Do not change the stack without discussing it.
- Pages are server-rendered and as light as possible: all CSS inlined in the page, no images (one exception: the home-screen icon PNG, below), no map SDK, no JavaScript except the inline theme switch and the one small inline script that fills in the second address (below); the page works without both. Nothing may block rendering: any script sits at the end of the body and only fills in extras after the page is shown, extra requests are asynchronous with a timeout, and the page is complete without them. The only other requests are the two self-hosted Geist Latin `woff2` files (`/fonts/`, one-year immutable cache). No third-party request of any kind.
- Design: "Console" (dark-first panels with hairline borders, Geist for labels, Geist Mono for data, one orange accent, dark and light themes; header = logo, GitHub icon, theme icon). Very little text: no taglines, hints or filler. No flag emoji (Windows does not render them).
- Implemented now: the home page with the lookup bar (a plain `GET /` form, field `q`), the "Your connection" panel (title "Lookup" for `/?<ip>`) and the Accuracy panel. The connection panel has two halves, the data rows FIRST (left on desktop, on top on a phone) and the place block with the map SECOND (right, below); the place is the city and country, country alone with no second line, or "Location unknown". Rows of the visitor's own page, in this order: IPv4, IPv6, DNS resolver, Network (no Prefix row, no AS number). Rows of a lookup page: the looked-up address (IPv4 or IPv6), Network, Prefix (the announced prefix, linked to its prefix page). The Network row (2026-11-15) is `BT-UK-AS · ISP · bt.net`: the network's short name (handle, from the loaded ASN data) as a link to `/as<n>`, its category (`$.metadata.category` of the row's json; `isp` shown as `ISP`, others with a capital first letter and spaces for underscores), its domain (`asn_domain`), joined by ` · `, an unknown part left out; with none known, or without ASN data, the organisation or name text of the ip2asn MMDB as plain text (else `AS<n>`, else a dash). The handle comes from the in-memory record; category and domain are read per page view with one parameterised query by number under the read lock of `asnFile` (`site/netinfo.go`), not kept in memory. The IPv4 and IPv6 values have a small copy button (inline SVG icon, `aria-label="Copy"`, rendered `hidden` and shown by `static/panel.js`; the other family's button is shown by `fill.js` when its address arrives); a click copies the address and shows a check mark for 1.5 s. `/?q=<ip>` and any non-canonical spelling of an address (upper case, percent-encoding, spaces, IPv4-mapped) redirect to the canonical `/?<ip>`; `/?q=<ip>` and any non-canonical spelling of an address (upper case, percent-encoding, spaces, IPv4-mapped) redirect to the canonical `/?<ip>`; what else the box takes is in "Lookup box" below, anything it cannot read gives 400 "Not an IP address, AS number or name"; a non-public address (`isPublic` in `site/lookup.go`) is shown with "Not a public address" and not looked up. Both MMDBs stay open for lookups and are swapped on change (`sync.RWMutex`, never closed under a lookup); a missing file only gives unknowns; addresses are never logged. The Accuracy numbers come from the stamp in the ip2geo MMDB's metadata (`description.openipdata`, written by `build-geo-data` `evaluate`): "right country" = `atlas_country_pct`, "right city" = `atlas_city_pct`, "of addresses have a city" = `city_pct`, the device count = `atlas_probes`, "updated" = `built_at`. The website reads no Postgres table and no status file.
- Unknown stays unknown: a missing score is shown as a dash, a missing city is not shown (the country stands alone, no second line), a missing location is "Location unknown"; never a sample, default or "estimated" value. The loopback connection is not a public visitor address.
- Cache: `/` shows the visitor's data, so it is `private, no-store` with no `ETag`; a lookup page (`/?<ip>`) shows none, so it is `public, max-age=300` (never put the visitor's own address on it); a bad query is `no-store`; an empty `q` (the empty lookup box) redirects to `/`, and the redirects to the canonical URL use the same cache header as a lookup page; a lookup page has the address in its `<title>`. Each MMDB is opened and watched in one place (`mmdbFile`); the scores are read from the metadata of the open ip2geo reader. The client IP is the header named by `REAL_IP_HEADER` (default `X-Real-IP`, also set in the unit, so a new binary under an older unit still works; set to empty = no header trusted, the TCP peer is the visitor), trusted only when the connection comes from loopback (nginx, which always overwrites that header with `$remote_addr`, the visitor after the Cloudflare real-IP step); a missing or invalid value means unknown, never the proxy's address. A non-loopback peer is the visitor itself, except a private or link-local peer while a header is set (a proxy moved off loopback): unknown. Site settings: `LISTEN`, `GEO_MMDB`, `ASN_MMDB` (default `/var/lib/openipdata-site/data/ip2asn-openipdata.mmdb`), `ASN_SQLITE` (default `/var/lib/openipdata-site/data/asn-openipdata.sqlite3`), `REAL_IP_HEADER`, set in the unit; `SHARE` (`on` default, `off`) and `SITE_ORIGIN` (default `https://openipdata.org`) are read by the binary and not set in the unit.
- Server (implemented, files in `infra/site/`; `site/README.md` has the commands): one Ubuntu 24.04 VM behind Cloudflare, installed by `infra/site/init-openipdata-site.sh` (idempotent, never overwrites the env file, never obtains the certificate). User `openipdata-site`; `/opt/openipdata-site/{bin,releases,slot-8080,slot-8081}`, the MMDBs and the ASN SQLite file in `/var/lib/openipdata-site/data`, updater state in `/var/lib/openipdata-site/state` (root), env `/etc/openipdata-site/openipdata-site.env` (`GITHUB_REPO`, `HC_PING_SITE`, `HC_PING_MMDB`; the site service reads no env file). Units: template `openipdata-site@.service` (hardened, instance name = port, `LISTEN=127.0.0.1:%i`, two instances `@8080` and `@8081` take turns), and oneshot plus timer for `openipdata-site-update` (root, 2 min), `openipdata-mmdb-pull` (as `openipdata-site`, 10 min) and `openipdata-cf-ips` (root, weekly). Updater (blue/green): reads the `.sha256` asset of the release `site` (missing, empty, invalid, download failed or binary hash different = upload in progress, try later, no ping), skips the installed hash, never retries the hash in `bad.sha256` (pings `/fail` each run). The symlink `/etc/nginx/conf.d/openipdata-site-live.conf` -> `/etc/nginx/openipdata-site/upstream-<port>.conf` is the ONLY record of the live port (no state file; missing link = fail, run the init script; the init script creates it once, pointing at 8080, and never changes it). Every run first starts the live instance if it is inactive. A new build goes to `releases/<sha>.tmp`, `-version` runs unprivileged under `timeout 10` (a binary that ignores the flag and starts a server must not block the updater), `slot-<idle>` is pointed at it, `openipdata-site@<idle>` restarted, and only `/healthz` = `ok <version>` within 20 s passes. A bad build never touches the live side: the idle instance is stopped, the slot restored, the hash goes to `bad.sha256`, `/fail` is pinged. A good build: the link is switched atomically, `nginx -t`, graceful `systemctl reload nginx` (skipped when nginx is not active); an nginx failure restores the link, stops the idle instance and pings `/fail` but does NOT mark the build bad. Only the live instance is enabled (new one enabled, old one disabled); after `DRAIN` s (10) the old instance is stopped; keeps the releases both slots point to plus the 3 newest. The init script migrates the old single `openipdata-site.service` once (starts `@8081` on the same release, switches the link, then removes the old unit and `current`; on failure the old service keeps running). Data puller (`openipdata-mmdb-pull`; MMDBs and the SQLite file): one conditional API call to the release `latest` (ETag saved in `.release.etag` with the body in `.release.json`, written only after a fully successful run; `If-None-Match`, 304 reuses the saved JSON and every file is still checked against its key), files `ip2geo-openipdata.mmdb`, `ip2asn-openipdata.mmdb` and `asn-openipdata.sqlite3` (the worker must publish the last one to the release `latest` first; until it does, with no local copy each run logs `not published yet`, which is not a failure; once a local copy exists, an absent asset is a failure), change key = asset `digest` or `updated_at|size` saved as `<name>.key`, size and digest checked, `.tmp` plus rename, an MMDB asset that is missing, or any failure, keeps the old file and pings `/fail`. nginx: `default-deny.conf` (catch-all 444 and `ssl_reject_handshake`, no certificate needed) is always enabled, so the origin is closed before the certificate exists; only Cloudflare ranges reach the site (a generated `geo` sets `$from_cloudflare`, others get 444; plain allow/deny cannot be used because it tests the address after realip), real IP from `CF-Connecting-IP`, ranges refreshed weekly and refused when empty or invalid, `nginx -t` before reload with the old file restored on failure, `/healthz` is a 404 through nginx, access log `/var/log/nginx/openipdata.org.access.log`. Certificate: certbot with the Cloudflare DNS challenge at `/etc/letsencrypt/live/openipdata.org/`, covering `openipdata.org` and `*.openipdata.org` (www is not served; any other host gets the default-deny answer), obtained by hand (the script prints the command; without the certificate the nginx site stays disabled), renewal hook reloads nginx. ufw: the real sshd ports (`sshd -T`, fallback OpenSSH profile or 22 with a warning), 80, 443. Pings: a normal run pings the URL, a failure pings `<url>/fail`, empty does nothing, URLs never logged.
- DNS resolver beacon (implemented, backend; files in `beacon/`, `infra/site/knot/`, `infra/site/systemd/openipdata-beacon.service`, `infra/site/nginx/r.openipdata.org.conf`; the init script sets it up when it knows the VM's public IPv4: the address of `v4.openipdata.org` (and of `v6.openipdata.org` for IPv6) when it is a global address of this machine, or `PUBLIC_IPV4`/`PUBLIC_IPV6` in the env file, which override; otherwise one line says it is skipped). A browser looks up the one-time name `<32 hex>.r.openipdata.org`; Knot DNS (listens only on the VM's public addresses and 127.0.0.1, port 53, UDP and TCP; zone from a generated file with a wildcard A/AAAA at the VM, TTL 0, serial = Unix time of the run that changed the content; `mod-rrl` 300 responses/s per prefix, slip 2; no zone transfer; no queries logged; ufw allows 53) sends each query by `mod-dnstap` to `/run/openipdata-beacon/dnstap.sock`; `openipdata-beacon` (own user, group `knot` on the runtime directory 0750, socket 0660, starts before Knot, binary `/opt/openipdata-site/bin/openipdata-beacon`, installed by `openipdata-site-update` from the asset `openipdata-beacon-linux-amd64` of the release `site`, a separate part that never stops the site update: bad build = old binary back, `/fail` ping) writes to Redis. Redis: `127.0.0.1:6379` only, no password, RDB snapshots on (`save 900 1`, `save 300 100`, `appendonly no`; since 2026-11-15, because the website keeps shared reports in it, see "Share"), `maxmemory 256mb` with `volatile-ttl` (keys that expire soonest go first: beacon keys, one hour or less, before reports, 30 days); the same Redis holds the `report:<id>` keys of the website. Contract with the site: key `beacon:<token>` (token = 32 lower-case hex, first label, case folded; any other name ignored), hash with ONE field `resolver_ip` (canonical address, IPv4 unmapped), `HSETNX` (first query wins) then `EXPIRE <BEACON_TTL>` only when the key was created (the binary default is 120 s; the unit sets `BEACON_TTL=3600` since a visitor may press Share minutes after the page loaded; the init script restarts `openipdata-beacon` when its installed unit file differs from the one in the repo); nothing else is stored (no EDNS client subnet, no query type) and no address, token or name is ever logged (only start settings and error counts). HTTPS on the one-time name: certificate `*.r.openipdata.org` by certbot with the DNS challenge answered by Knot (`python3-certbot-dns-rfc2136`; a TSIG key made once by the init script into `/etc/knot/openipdata-acme-key.conf` and `/etc/letsencrypt/openipdata-r-rfc2136.ini`, root only, never shown; the Knot ACL lets only that key, from 127.0.0.1, update TXT at `_acme-challenge` of the zone; `zonefile-sync: -1` so Knot never writes the generated zone file); like the main certificate the script never obtains it and prints the command. `nginx/r.openipdata.org.conf` (enabled only with that certificate) matches only `<32 hex>.r.openipdata.org`, refuses Cloudflare peers (403), serves only `GET`/`HEAD` of `/` as `/resolver?t=<token>` on the live site with `X-Real-IP` = TCP peer, 10 r/s per address, own log with status and time only, adds no CORS header. The site's DNS row is OFF by default (`BEACON_ZONE` empty in the binary); the init script writes the drop-in `/etc/systemd/system/openipdata-site@.service.d/beacon.conf` (`BEACON_ZONE=r.openipdata.org`, `REDIS_ADDR=127.0.0.1:6379`) only while that nginx site is enabled and removes it otherwise, restarting the live site instance only when the drop-in changed. The site unit's hardening allows the loopback TCP connection to Redis (no `IPAddressDeny`, no `PrivateNetwork`).
- Both addresses (decided 2026-11-15): a browser connects over one family, so `GET /ip` (and HEAD; `text/plain`, canonical address plus newline, `no-store`, `Access-Control-Allow-Origin: *`, 503 `unknown` when unknown, same `clientAddr` rules, never logged) answers the visitor's own address, and the page asks the other family on a name that exists in one family only: `v4.openipdata.org` (A record only) and `v6.openipdata.org` (AAAA record only), DNS-only names that point straight at the web VM, NOT through Cloudflare (`openipdata.org` stays behind it); they expose the VM's address by design. The wildcard certificate covers them. Their nginx file `infra/site/nginx/v46.openipdata.org.conf` (installed and enabled like the main file) accepts direct visitors only: a request whose TCP peer is a Cloudflare address (`$from_cloudflare` = 1) gets 403 on every path and both ports, because a proxied request would show Cloudflare's address as the visitor's second address (the address is `$realip_remote_addr`, the TCP peer, so a client's `CF-Connecting-IP` never counts), serves only `location = /` (GET and HEAD, proxied to `/ip` with `X-Real-IP` always set), answers 404 for every other path without reaching the site, limits each address (`limit_req`, 5 r/s), has a 1k body limit and its own access log without addresses. Settings in the unit: `V4_URL` (default `https://v4.openipdata.org/`) and `V6_URL` (default `https://v6.openipdata.org/`), each an absolute `https://` URL (`http://` only for `127.0.0.1`/`localhost`) or empty; empty for the missing family = no second row and no script. The visitor's own page (public address only) shows an IPv4 row and an IPv6 row; the server fills its own family, the other shows a dash that the script (`site/static/fill.js`, last thing in the body, starts after the HTML is parsed, 4 s abort, strict check of the answer, `textContent` only) fills in. That script, `resolver.js` (the DNS row, below) and `panel.js` (copy and share buttons, see "Share") are the ONLY JavaScript besides the theme scripts. The page requests plain `<url>`; only after the visitor pressed Share does `panel.js` request `<url>?r=<report id>` once more, so `/ip` can add the address to the report (nginx passes the query string: `proxy_pass` with a URI keeps the arguments). The five scripts (`site/static/head.js`, `theme.js`, `fill.js`, `resolver.js`, `panel.js`) are plain files embedded with `go:embed` and put inline into the page; the CSP hashes come from the same text at start (`scriptText` in `site/page.go`), and an empty file stops the start. Its hash is in `script-src` and `connect-src` lists exactly the origins of the two URLs, only on a page that has the row (every other page keeps the CSP without both). No resource hints for the two hosts.
- DNS row (implemented 2026-11-15, site part; code `site/resolver.go`, `site/redis.go`, `site/static/resolver.js`; backend in the "DNS resolver beacon" bullet): the visitor's own page (public address only) gets a row "DNS resolver" (a dash, hidden behind three CSS-only waiting dots for about a minute at most) that `resolver.js` (last in the body, after `fill.js`, own CSP hash, `connect-src https://*.<zone>` only on that page) fills like the owner's other site does: the resolver's IP ADDRESS as a link to its lookup page `/?<ip>`, then the SHORT network name (the `name` of the ip2asn record, e.g. `GOOGLE`; the organisation only when there is no name) as a link to the organisation page; no AS number. The script makes its own 32-hex token with `crypto.getRandomValues` (the server makes none; the report id never appears in a DNS name) and leaves it in `data-t` of the `#dns` element, where `panel.js` reads it when Share is pressed; it fetches `https://<token>.r.openipdata.org/` (first a request to `/t` of that name that only causes the DNS lookup (nginx answers 204, the site is not asked), then, 2.2 s later (Knot reports lookups in batches up to two seconds late), `/` of that name; after a 404 again every 2 s, 30 tries in all (about a minute), 3 s abort each; any other failure leaves the dash; the site never holds a request open to wait); nginx proxies that to the site's `GET /resolver?t=<token>`, which reads `HGET beacon:<token> resolver_ip` from Redis on loopback with a tiny standard-library client (300 ms deadline, no dependency) and answers JSON `{"ip","name","org"}` (`org` = `/asn-<slug>` or, without a slug, `/as<n>`; unknown fields left out; 404 not there yet, 503 Redis down, 400 bad token; `no-store`, `Access-Control-Allow-Origin: *`). `/resolver` only reads; it never touches a shared report (the report reads `beacon:<token>` itself, see "Share"). The resolver address is sent to the page (it is the resolver's, not the visitor's); neither it nor the token is ever logged. Settings: `BEACON_ZONE` (EMPTY by default = no row, no script, `/resolver` 404; the init script sets it in a drop-in only while the nginx site of `r.openipdata.org` is enabled, so the row never appears before the chain works) and `REDIS_ADDR` (loopback only, default `127.0.0.1:6379`).
- ASN pages (implemented 2026-11-15; code in `site/asn.go` and `site/asnpages.go`, templates `layout.html` (shared header and lookup bar) and `asn.html`, styles `static/asn.css`, added to the page only on ASN pages so the home page does not grow; no new script, the same two inline theme scripts). Data: the SQLite file `asn-openipdata.sqlite3` (tables as written by `hatchet/asn/export.go`: `asn`, `asn_domain`), opened read-only and immutable (`file:...?mode=ro&immutable=1`), loaded again when its size or mtime changes (checked every 30 s with the MMDBs; `asnFile`, same care as `mmdbFile`: read and built outside the lock, swapped under the write lock, the old handle closed only after the swap; requests render into a buffer while they hold the read lock, never write to the client under it; one log line per distinct error with the path; a failed reload or a vanished file keeps what is loaded). One compact record per network is kept in memory (number, handle, organization, slug, country code, IPv4 and IPv6 amounts, prefix counts), never the JSON: the prefix counts and the country name come out of SQLite's `json_array_length` and `json_extract` (guarded by `json_valid`) while the table is read once per load; the announced prefixes of every network go into one compact sorted index (see the prefix pages). Network page and JSON read their one row (and `asn_domain`) per request. `ASN_SQLITE` missing, unreadable or not a database is never fatal: the ASN pages answer 503 "ASN data is not loaded" (`no-store`, `Retry-After`), the API 503 JSON, the Network row of the connection panel is the plain MMDB text, the rest of the site works. Routes: `/as<number>` (number 1 to 4294967295; `/AS15169`, `/as015169` redirect 301 to the canonical lower-case form with no leading zeros, also without data; 0 or out of range is a 404 page), `/asn-<slug>` (organization; slug `[a-z0-9-]`, 1 to 255 characters, lower case only, anything else is a 404 page), `/top-asn-by-ip-address`, `/top-asn-by-ipv6`, `/top-organizations-by-ip-address`, `/list-of-countries-by-ipv4-allocation`, `/api/as<number>` (JSON `{"asn","domain"?,"data"}`, `data` = the `json` column as is, `domain` left out when unknown; only the canonical spelling is served, 404 JSON for the rest). Input `AS15169` / `as15169` / `15169` in the lookup bar or `/?AS15169` / `/?15169` redirects (302) to `/as15169` (see "Lookup box"). Caps: network page 500 prefixes per family (one line with the totals and a link to the JSON, which has all), "Same organization" 100 other networks by number (link to the organization page when more), organization page 500 networks biggest first (one line with how many more), the three top lists 100 rows, all countries on the country list. Ranking rules: only networks with a positive amount, ties by number; organizations are ranked by summed IPv4 addresses over networks with a valid slug (no slug = not in the organization list); countries are summed by the network's country code (no code = no country) with the name found in the data (`metadata.country`), no country table. IPv6 amounts are shown as a number of /64 networks (addresses / 2^64) everywhere (`fmtV6`: whole number with thousands separators, `<1` for a positive amount below one /64, `0` for none; column "IPv6 /64s", ranking title "Top networks by IPv6 space"; the JSON is unchanged). ## VM

## Rules

- Keep it simple: read env vars directly in `main.go`; no config packages or frameworks.
- Use the standard library where possible (e.g. `encoding/json`).
- Postgres is the source of truth; the VM only keeps caches and the last few builds.
- Output files (MMDB, SQLite) are rebuilt from scratch each run and written via a `.tmp` file plus rename.
- One writer per table; every other workflow only reads it:
  `public.asn` ← `build-asn-data`, `public.asn_geo_pdb` ← `sync-peeringdb`, `public.asn_domain` ← `update-asn-domains`,
  `public.geo_ix_pdb` ← `sync-peeringdb`, `public.geo_eval` ← `build-geo-data`, `public.geofeed_urls` ← `sync-geofeeds`,
  `public.visitor_ips` ← external websites insert through `iplistener` (insert, or update of `last_seen_at` only); `resolve-ips` is its only deleter (exception to one writer: it never inserts or updates),
  `public.network_traces`, `public.traced_networks`, `public.ip_ptr_names`, `public.customer_name_networks` and `public.rdns_geo_layer` ← `resolve-ips`,
  `public.rdns_city_rules` and `public.rdns_llm_answers` ← `learn-rdns-rules`,
  `public.mlab_hop_names` ← `import-mlab`.
- Schema changes go in `hatchet/schema` (idempotent `IF NOT EXISTS` statements), never by hand. A workflow runs DDL only
  for tables it writes: `ALTER TABLE` takes an ACCESS EXCLUSIVE lock even when the column exists.
- Do not delete rows from `public.asn`; ASNs missing from the source are kept for now.
  `build-asn-data` sets `public.asn.seen_at` for every ASN in the source each run; readers use it to ignore old rows
  (NULL = not yet seen since the column was added).
- `public.asn_geo_pdb` mirrors PeeringDB: `sync-peeringdb` replaces it in one transaction each run, together with
  `public.geo_ix_pdb` (global unicast internet exchange peering LAN prefixes with the exchange's country and city).
  An asn_geo_pdb shrink refuses the whole replace; a geo_ix_pdb shrink or empty result only keeps the old
  geo_ix_pdb rows (`StoreStats.IXKept`) and asn_geo_pdb is still replaced.
- `build-geo-data` only reads these tables and runs DDL only for `public.geo_eval` (`schema.EnsureGeoEval`), never `schema.Ensure`. A missing or empty `public.geo_ix_pdb`
  skips the `50-ix` layer for that run, and missing facility columns or no matching network skip `40-hosting`
  (`Source.SkippedLayers`); a `50-ix` of 1 to 199 usable rows fails, `40-hosting` has no minimum. Exchanges without a
  city are never written to `50-ix`.
  `asn_geo_pdb.fac_count`/`fac_city`/`fac_country` (facilities only, city set only if all are in one city) feed `40-hosting`.
- ip2geo layers have ONE format and ONE name in every stage: a gzipped CSV in the geofeed (RFC 8805) layout, header
  `prefix,country,region,city,source`, named `NN-name.csv.gz` (`10-rir`, `20-ipverse`, `25-bgp`, `30-pdb`, `35-rdns-wide`, `36-mlab`, `40-hosting`,
  `38-asn-geofeed`, `50-ix`, `60-whois`, `65-rdns`, `67-rdns-names`, `70-geofeeds`; the number is the order). `build-geo-data` `download` empties its layers dir, each
  source writes its file through the one shared writer (`.tmp` plus rename), and the R2 layers are put in as they are (see the R2 rule below: the last download of each stays in `geo/downloads/` with its ETag, and an unchanged object is copied from there).
  The build passes every `*.csv.gz` in the dir, sorted by name, to `mmdbbuilder geo` (one reader, columns found by header);
  there is no per-layer code and no layer list in the build. Special rules live only in `layerRules` (`geo/pipeline.go`),
  one line per layer name; a rule for an absent file is not passed. A new layer is a new file name, not new code.

  `Source.SkippedLayers` for reporting (the three rDNS layers are written from `public.rdns_geo_layer` by scope (`wide`, `traced`, `named`), all
  with `-same-country`: they add cities, never change a country); `38-asn-geofeed` is the ASN dominant geofeed city: an ASN whose own geofeed rows (from `70-geofeeds`, attributed by the longest announced prefix of `public.asn` containing them; prefixes announced by more than one ASN are ignored) cover at least half of its announced addresses (per address family) and put at least 80% of the addresses of their geofeed rows (rows without a city count in the total) in one city, from at least 2 rows, gives that city to all its announced prefixes (`-same-country`); `download` reads `public.asn` once and saves the prefixes in `geo/asn-prefixes.csv.gz` (outside the layers dir), and the holdout build recomputes the layer from the kept feeds so held-out feeds never reach it; an R2 layer (`60-whois`, `70-geofeeds`) that is missing or older than 3 days skips the `HC_PING_GEO` ping.

A missing object, one older than `mlabMaxAge` = 45 days (by the object's modified time; the export is made by hand about monthly) or any other fetch error only skips the layer (`Source.SkippedLayers`, a warning) and NEVER adds to `StaleLayers`, so the `HC_PING_GEO` ping is still sent. The holdout build passes the file as it is (it does not learn from the geofeed rows directly; its MMDB-hop part reads the published MMDB, which holds geofeed cities, like the MMDB hop votes of `35-rdns-wide`).
  `25-bgp` is the BGP community city: `sync-bgp` (see its bullet) leaves the community values of every IPv4 prefix of a RIPE RIS table in R2 (`internal/bgp/communities.csv.gz`); `build-geo-data` `download` fetches it with the same Stat, ETag and saved-copy rule (saved as `geo/downloads/bgp-communities.csv.gz`, never in the layers dir) after the geofeed layer is there (`geo/bgp.go`, `-same-country`, below `30-pdb` so every other layer replaces it and it only shows where nothing else gives a city). Rules (constants `bgpMin*` in `geo/bgp.go`): a prefix owns its addresses minus the more specific prefixes of the file; it has a known city when geofeed rows with a city cover at least 50% of its owned addresses and at least 80% of those are in one city (country and normalised name; a more specific feed row wins, a repeated prefix: the last row); a value is a rule when at least 3 known prefixes carry it, at least 80% of them are in its top city and at least 90% in its top country; a prefix gets a city when it has at least one rule among its values and all its rules name the same city (a disagreement gives nothing), and only its owned parts are written (`bgp` as source). A missing object, one older than 3 days, any R2 error, an unreadable file or no row only skips the layer (`SkippedLayers`, a warning): unlike `60-whois` and `70-geofeeds` it never skips the `HC_PING_GEO` ping. The holdout build recomputes the layer from the kept feeds and the same saved file, so held-out feeds never reach it. `Source` counts `bgp_rules`, `bgp_known_prefixes` and `bgp_prefixes`.
- **ASN main city fill (`80-asn-main`, a guess)**: not a layer file and not in `layerRules`/`optionalLayers`; it is the one derived fill done inside the builder, because it needs the merged result of all layers. `mmdbbuilder geo -asn-main <asn-prefixes.csv.gz>` (the file `download` saves in `geo/`, gzipped CSV `asn,prefix`) runs after all layers and before the write. IPv4 only (IPv6 rows are ignored; it was measured on IPv4 only). An address belongs to the ASN of the longest announced prefix containing it; a prefix announced by more than one ASN belongs to nobody and still shadows broader prefixes (as in `38-asn-geofeed`). Per group (ASN, country) the addresses that already have a city are counted per city (case-insensitive; when the build has `-geonames`, only cities the GeoNames index places count, the measured definition: cities it cannot place are ignored for the counts but never overwritten; without the index every city counts; written with the most common spelling, ties by name); the group qualifies when its main city (ties: smallest name) holds at least `asnMainMinShare` = 90% of them and the group has at least `asnMainMinAddrs` = 256 such addresses. Every part of a network of that country that has NO city and belongs to a qualifying group's ASN gets the main city, `city_source` = `80-asn-main`, and coordinates by the same GeoNames rule as layers. It only fills (new insert rule: same `country_code` and no `city_name`); a city or a country is never replaced or changed; the output is deterministic and without the flag byte-identical to a build without it. Measured on RIPE Atlas: right 48% of the time (520 of 1,083 gap probes), fills about 25% of the gap. Printed as `layer 80-asn-main: R rows, P prefixes, 0 skipped` plus `asn-main: G groups qualified of T, A addresses filled`. Guesses are no evidence for our own pipeline: `mmdbbuilder gaps` still lists their /24s (`sample-names` keeps sampling them) and `mmdbbuilder lookup -in/-out` (the MMDB hop votes of `locate`) writes no row for them; the plain `lookup` report shows them, and `eval` scores them like any record (`layer_80_asn_main_*` show the fill alone; `city_pct`, `atlas_city_*` and the holdout city score count the guessed cities like any other, so the first build with the fill moves them; the publish gate checks only country scores and the fill never changes a country). `build-mmdb` passes `-asn-main` when `geo/asn-prefixes.csv.gz` exists (`BuildMMDBOutput.ASNMain` = `on` or `skipped: no ASN prefixes`); a file that cannot be read or has no rows gives `asn_main: skipped: ASN prefixes unreadable` and no flag (never a failed build; the holdout build skips too); `download` deletes that file at the start of its ASN step and writes it again only when it reads `public.asn` (needs the geofeed layer), so a file that is there always belongs to the layers of the same run, never to an older one. The holdout build passes it too, so the fill is recomputed from the kept feeds and held-out feeds never reach it.
- `public.asn_domain` holds the final domain per ASN (`source` = `pdb` or `rdap`); PeeringDB wins over RDAP.
  Domain cleanup rules (registered domain, rejection list) live in `hatchet/domains/clean.go`.

  `public.visitor_ips` (DDL only `schema.EnsureVisitorIPs`: `CREATE TABLE IF NOT EXISTS`, so it never locks the table the websites write; deletes: `trace` removes all but the newest visitor IP
  (`last_seen_at`, then `ip`) of each /24 it just stored traces for, in the transaction that stores them, and `locate` removes every visitor IP of a `located` /24 after its commit; counts only in the outputs),
  `public.generated_rules` (read only; a missing table means no rules; a rule without domains applies to every name) and `public.asn` (only the IPv4 prefixes of `json`, extracted in SQL, kept in memory), and runs
  DDL only for its own tables (`schema.EnsureRDNS`), never `schema.Ensure`. That DDL runs once per workflow run, in the first task
  (`pick-networks`, which the `run-rdns` command also starts with: `connectEnsure`); `trace`, `resolve-names` and `locate` open their connections
  with no DDL (`connect`), because `ALTER TABLE ... IF NOT EXISTS` takes an ACCESS EXCLUSIVE lock even when the column exists, and `build-geo-data` reads `public.rdns_geo_layer`. IPv4 only, global unicast only. Visitor IPs and every
  traced IP stay in Postgres and in the batch file under `/var/lib/openipdata/rdns/`: never in Hatchet task inputs, outputs, log
  lines or returned errors (tasks report counts; errors that could quote an IP are replaced by `dbError` or `scrubIPs`).
  `pick-networks` writes the batch file that `trace` reads. `public.network_traces.candidates` (`inet[]`, added by `schema.EnsureRDNS`) holds the candidates of a trace (the target, then the last quarter of the
  public hops, closest first): `trace` stores them with the path, and `locate` reads only `prefix`, `target_kind`, `target` and `candidates`, never `hops` or `hop_ips`; `resolve-names` reads the same plus `hop_ips`, never `hops`
  (`public.network_traces.hop_ips`, `inet[]`, added by `schema.EnsureRDNS`: every public answering hop of the path, target left out, each IP once; `trace` stores it, rows with NULL are filled once from `hops` at the start of `resolve-names` only; the stat `reached_asn` is "a tail hop candidate, not the target itself, is in the target's ASN"). Rows written before the column existed (NULL) are filled once from `hops`
  in chunks at the start of `resolve-names` (and of a `locate` that rebuilds). `resolve-names` names the candidates and every public hop (`hop_ips`) of the newest trace per prefix and kind of the last 7 days, never replacing an `ok`/`not_found` name by an `error`; `locate` reads only the names of its candidates. `locate` replaces `public.rdns_geo_layer` in one transaction and
  refuses a shrink of more than 10% of the sticky rows (traced rows with method `rdns_rule`, which a legacy rule located) when the table had any (`ErrShrink`; `force_replace` overrides). Candidate traced rows and all wide rows are volatile: recomputed every rebuild and re-learned rules change them daily, so they are not guarded; `previous_volatile` and `stored_volatile` in the output report their counts before and after. `locate` is skipped (`skipped` in its output, table untouched) when a fingerprint of its inputs
  (count and newest timestamp of the traces of the 180-day window, of the usable `ip_ptr_names` and of the current ASNs, and hashes of `generated_rules` and `rdns_city_rules` content/version/status, all computed in SQL)
  equals the one saved after the last rebuild and that rebuild is less than 24 hours old; the fingerprint and the rebuild time are in `/var/lib/openipdata/rdns/locate-state.json`
  (`.tmp` plus rename, written only after a committed rebuild; losing it only costs a rebuild). `force_replace` always rebuilds.
  **MMDB hop fallback**: `locate` reads its own copy of our published ip2geo MMDB from the private R2 bucket (`Pipeline.R2`, the `R2` env setting), never `build-geo-data`'s files on the VM: it
  stats today's (UTC) dated key `<YYYY-MM-DD>/ip2geo-openipdata-<YYYYMMDD>.mmdb`, else yesterday's, keeps the object as `/var/lib/openipdata/rdns/ip2geo.mmdb` with its ETag in `ip2geo.mmdb.etag`, and downloads it
  (`publish.R2.DownloadIfChanged`) only when the ETag differs and only when `locate` rebuilds. The ETag of the MMDB that is read (or `none`) is part of the fingerprint, so a new MMDB triggers a rebuild.
  An R2 outage must not change the rows (a rebuild without the MMDB votes could hit `ErrShrink`): when R2 cannot be used (no R2 setting, a Stat error, no object for both days, or a failed download) the saved copy is
  read instead if `ip2geo.mmdb` has its ETag beside it, and that saved ETag is in the fingerprint (`mmdb: saved copy` and `mmdb_reason` in the output, a logged warning; after a failed download the fingerprint names the saved copy,
  so the next run tries R2 again). Only with no usable saved copy, or when `mmdbbuilder lookup` exits non-zero on it (the copy and its ETag are then deleted), is the fallback skipped (`mmdb: skipped`, fingerprint `none`
  so the next run tries again); `locate` still succeeds.
  A /24 that no trace of gets a rule match casts ONE wide vote (never a traced row) for the city of the first router hop (never the target itself; traces by kind order, hops closest first, same-ASN hops first,
  as `matchTrace` tries them) that has a city in the MMDB; no origin ASN, no vote. Rule votes and MMDB votes count the same. `locate` writes the hop IPs (only those of no-match /24s, plus the winning
  router of rule-matched /24s for the agreement counts `mmdb_compared`/`mmdb_agreed`) to `rdns/mmdb-hops.txt`, runs `mmdbbuilder lookup -db <mmdb> -in <ips> -out <tsv>` (`ip<TAB>country<TAB>city`, only IPs with a city;

  `rdns_rule` for a wide row that at least one legacy rule voted for, `mmdb_hop` for a wide row of MMDB votes only; wide rows also hold `rule_votes` and `mmdb_votes` for their city (the columns are added by `schema.EnsureRDNS`).
  `build-geo-data` reads prefix, country and city by scope and ignores these columns.
  **`sample-names`** (after `resolve-names`; `locate` has it as a parent; 30 minute timeout; customer PTR names in the gap; DDL in `schema.EnsureRDNS`) samples the gap: the IPv4 /24s that our published ip2geo MMDB gives a country but no city (about 69% of IPv4).
  It gets the MMDB the way `locate` does (one shared code path, `useMMDB`: stat R2, ETag, saved copy) and runs `mmdbbuilder gaps` on it only when the ETag of the MMDB it reads differs from the one saved beside `gaps.txt` (both in the rdns dir);
  with no usable MMDB, or a failing `mmdbbuilder gaps`, it reports `skipped: <reason>` and succeeds. A run less than 25 minutes after `last_run` does nothing (`skipped: recent`), so chained runs sample at most once per 30 minutes.
  The order is a fixed walk over all 2^24 /24 indexes, `(i*0x9E3779 + 0x5A5A5B) mod 2^24` (a bijection); the cursor, `cycle_started` and `last_run` are in `sample-state.json` in the rdns dir (`.tmp` plus rename; losing it restarts the cycle from 0, which only samples some /24s again early).
  Each run walks from the cursor (at most 100,000 steps), takes the indexes that are in the gap list (binary search over the runs; a /24 whose `.1` is not public is dropped) until it has `sampleNetworks` = 2000, takes the `.1` and two distinct random hosts from `.2` to `.254` of each (never `.0` or `.255`), and looks them up with the `resolve-names` resolver
  (`ptrResolver`, DoH fallback, `resolveAll`; its lookups only: `ip_ptr_names`, `storeNames` and `freshNames` are not used, so `resolve-names` is not affected), 160 /24s at a time. Only a /24 with at least one `ok` name is recorded, in `public.customer_name_networks`
  (`prefix` cidr key, `country` of the gap run, `hosts` inet[] = the hosts with a name, `names` text[] = their PTR names in the same order, `sampled_at`); a /24 with no name gets no row. The cursor moves only past batches that were recorded; a soft budget of 25 minutes ends the lookups cleanly
  (`stopped: time`, the unfinished batch is drawn again later). When the walk passes 2^24 the cycle is done; the next starts `cycle_started` + 180 days, until then the task reports `skipped: cycle done`. Rows older than 200 days are deleted (the window of `locate` and the learner is the same 200 days, longer than a cycle, so a /24 stays until its resample).
  A DNS problem never fails the task: only a database error (`dbError`) and cancellation do. The output has counts only (`gaps`, `steps`, `picked`, `queried`, `ok`, `not_found`, `errors`, `doh`, `networks`, `named_networks`, `pruned`, `cycle_done`, `mmdb`, `skipped`).
  `locate` reads `customer_name_networks` rows of the last 200 days directly (prefix, country, hosts and names; no join; a missing table means none) and tries, per name, the legacy `generated_rules` and then the candidate rules of `rdns_city_rules` (ranks in order), as for target names; a /24 gets the city with
  most of its names (a tie gives none) when the city's country is the row's `country`, as a row of the NEW scope `named` in `public.rdns_geo_layer` (`router_ip` = the first host that gave the winning city, a legacy match preferred, `router_ptr`, `rule_name` and `method` (`rdns_rule` or `candidate_rule`) as for traced rows, `same_asn` NULL). Named rows are volatile:
  recomputed every rebuild, never carried, not sticky (not in `isSticky`, so not in the shrink guard), never marking `traced_networks` located (`markLocatedSQL` reads the `traced` scope only), never casting a wide vote, and ignored by `readTracedRows` and by the refresh and retry reads of `resolve-names` (all select `scope = 'traced'`);
  the output counts them apart (`named`, `previous_named`, `stored_named`, `named_ties`, `named_foreign`, and `customer_*`), and `previous_volatile`/`stored_volatile` stay candidate and wide rows. The fingerprint holds the UTC day of the newest `sampled_at` of those rows, so new samples cause at most one extra rebuild a day (a rule change still rebuilds at once).
  `build-geo-data` writes the scope as the optional layer `67-rdns-names` (`-same-country`). `learn-rdns-rules` (`readDomainNames`, so `propose-codes` too) also reads the names of those rows (last 200 days, no DDL, a missing table means none), with the row's `country`, which `loadRouterCountries` does not overwrite (it only fills names with no country);
  at most `customerNamesPerDomain` = 5000 per registered domain stay (the smallest FNV-1a hash of the IP, kept in a bounded heap, so the set is stable); router names are not capped and win over a customer row for the same IP. `readDomainNames` also reads the `ok` names of `public.mlab_hop_names` (see `import-mlab`; no DDL, a missing table means none) as ROUTER names with no country (`loadRouterCountries` fills it), at most `mlabNamesPerDomain` = 5000 per registered domain with the same smallest-hash selection (`collectCustomer`); the order is traces, then hop names, then customer names, so a traced name wins over a hop name and a hop name over a customer name for the same IP. The learner and the pattern redaction (`llmpatterns.go`) are unchanged.
  **Schedule** (`public.traced_networks`, one row per traced /24, `resolve-ips` the only writer, created by `schema.EnsureRDNS`; pure rules in `rdns/schedule.go`): `status` is `silent` (no hop answered in the /24's new traces),
  `unmatched` (hops answered, no city) or `located`; `attempts` counts consecutive traces with the same non-located status; `next_trace_at` NULL means "only when a visitor comes again". Silent: next trace after 7 days, at most 3 attempts, then NULL.
  Unmatched: after attempt 1, 2, 3 wait 7, 20, 60 days, then NULL. NULL rows are traced again only when a visitor of the /24 has `last_seen_at` newer than `last_traced_at` and that trace is at least 60 days old (attempts restart).
  Located: recheck 150 days after the last trace, whatever the visitors do; a recheck keeps the old city unless it finds one. `trace` writes silent/provisional `unmatched` (a located /24 stays located) in the transaction that stores the traces;
  `locate` makes the /24s of its traced rows `located` in the transaction that replaces the layer. `pick-networks` (limit 1000, `PickOutput.Limit`) picks, in this order: /24s with no row and a visitor seen in the last 30 days (most visitors first),
  then rows with `next_trace_at <= now()` (oldest first), then visitor-revived NULL rows (oldest trace first). Targets: newest visitor IP (if the /24 has one; it is optional in the batch file), `.1` and a random host. The first `pick-networks` after the table
  was added (table empty) backfills it from `network_traces` and `rdns_geo_layer` (located if the layer has a traced row, else unmatched/silent from the newest traces, attempts 1). `trace` also deletes `network_traces` rows older than 200 days and
  `traced_networks` rows that are not located, have no `next_trace_at` and were last traced more than 200 days ago, and reports `path_compared`/`path_changed` (the two newest traces per prefix and kind, candidates without the target; counts only).
  **Located /24s stay**: `locate` only uses the newest round of traces of a /24 (those within an hour of its newest), keeps every traced row of the current layer that a legacy rule found (never a `candidate_rule` row) whose /24 no trace located in this rebuild (same columns, same `located_at`) and
  counts it as a rule vote for its announced prefix (a carried /24 casts no other vote); a row located by a trace gets that trace's time as `located_at`. The shrink guard counts the carried rows (they are sticky). `resolve-names` also looks up again up to 500
  answers per run older than 30 days that belong to located /24s (legacy traced rows only, never `candidate_rule` rows: routers of traced rows, candidates of their newest traces), oldest first (`refreshed`), with the same no-overwrite-on-error rule. Every lookup sets `public.ip_ptr_names.tried_at` (an error that does not overwrite a stored `ok`/`not_found` row moves only `tried_at`); the refresh skips IPs tried in the last 7 days, so failing names cannot hold its slots. Freshness for the normal lookups stays on `resolved_at`. `public.ip_ptr_names.error_count` (added by `schema.EnsureRDNS`) counts failed lookups in a row (each error adds one, also when it only moves `tried_at` on a stored `ok`/`not_found` row; `ok`/`not_found` reset it to 0): an IP whose last lookup failed is not looked up again until `tried_at` plus 1 day (1 error), 2 days (2) or 7 days (3 or more); an old `error` row with NULL count is a first failure. The refresh uses the same wait, and a bounded retry pass looks up due failures that no trace of the last 7 days names any more but a 180-day trace candidate or a carried traced router still does. `resolve-names` reports `errors`, `errors_timeout`, `errors_servfail`, `errors_other` (kind of the final answer after the DoH fallback), `backed_off` and `retried`, counts only.
  When a Hatchet run picked its full limit and `trace` stored traces, its successful `locate` task starts a new `resolve-ips` run (not a child; `chained` in the output; the `rdns` limit queues it behind the current run); never from `run-rdns`.
- `learn-rdns-rules` (daily 05:00 UTC, task `learn`, own `rdns-rules` limit; CLI `run-rdns-rules`) reads the PTR names of every IP of the traces of the last 180 days (target, candidates and `hop_ips`, each IP once; `hop_ips` is skipped while the column does not exist), successful PTR names and current ASN prefixes. It learns up to 3 extractions per registered domain (`rdns_city_rules` keyed by `(domain, rank)`, rank 1 to 3): rank 1 on all names, rank 2 on the names rank 1 does not decode, rank 3 likewise, each from at least 3 distinct IPs with distinct names that decode on those names (the regex is still checked against all the domain's names); `locate` tries a domain's ranks in order. Stop list (`roleTokens` in `rdnsrules/learn.go`): router role tokens (`ccr`, `core`, `gw`, ...), common network/product words (`ip`, `pool`, `sub`, `isp`, `res`, `biz`, ...) and all US state and Canadian province codes are never decoded from any dictionary (scoped manual/LLM overrides still can). GeoNames only gives tokens of 4+ letters and places of at least 15,000 people (applied after the 10x namesake rule). An extraction needs at least 2 distinct decoded token values at every rank (no single-valued rules). Domestic gate: when at least 80% of a domain's routers with a known country are in one country, a rule needs `country_agree` >= 0.7 (global carriers stay ungated); names with a label outside `[a-z0-9-]` are skipped (`names_skipped`); the output separates `unsupported` (observed domains below the floor) from `lost_support` (stored rules with no current names, kept) and `retired` (see below). The announced-prefix read is shared in `hatchet/ipdata` (Postgres 15 compatible). OurAirports, UN/LOCODE and GeoNames have their own monthly cache in `rdnsrules/dictionaries/`, never another workflow's files. Only this workflow writes `public.rdns_city_rules` and runs `schema.EnsureRDNSCityRules`, which fails with the fixed `schema.ErrOldRuleLayout` (never drops or alters) when the table has the old per-domain layout without `rank`. Pattern, effective token-to-city mappings and version are published atomically; failed refreshes and loss of support (a domain with NO current names) keep old rules. For a domain WITH current names, a stored `origin = learned` row this run does not reproduce is retired: `status = rejected` and its version added to `rejected_versions` (so it cannot come back unchanged; a row whose content moved to another rank is deleted as a stale duplicate); manual/LLM rows are never retired. Candidate rows are volatile in `locate`, so its shrink guard is unaffected. Unchanged content preserves status/measurements (also when it moves to another rank), changed content becomes a candidate; a rank the learner no longer produces keeps its last row only while the domain has no current names. Scoped manual/LLM overrides of any rank of a domain retain provenance and apply to the rank that now has their extraction; entry and active promotion are future work.
  `run-rdns-rules -reject example.net` (comma-separated) or `reject_domains` workflow input withdraws the current versions of every rank of the domain without downloads/learning. Rejected content hashes are retained per row, and a version withdrawn at one rank cannot return at another. `resolve-ips` reads the table without DDL; missing means no candidates. Only `candidate` rows are consumed in v1, after all legacy matches and carried rows, before MMDB fallback. For a /24 with no legacy match and no carried row, a candidate is tried on the target names of its traces first (by kind), then on router hops (same ordering as MMDB; hops need a known target origin), a domain's ranks in order; a match casts at most one wide vote per /24 and, when it is a target or a hop of the target's ASN, also writes a traced row with method `candidate_rule` (`rule_name` `<domain>#<rank>`). Those rows are never sticky (never carried, recomputed each rebuild; `readTracedRows`, `markLocatedSQL`, the schedule backfills and the refresh/retry reads of located names ignore them) and never mark a network located; only `generated_rules` rows are sticky and located. All votes weigh equally. Wide rows count `candidate_votes`; method is `rdns_rule` if any legacy vote supports the winner, else `candidate_rule` if any candidate vote does, else `mmdb_hop`. Fingerprinting includes rank/effective mappings/version/status, so withdrawal removes the rows and recalculates votes on the next rebuild, subject to the existing shrink guard (only the sticky rows are guarded, so a withdrawal of candidate rules never needs `force_replace`; the swing shows in `previous_volatile`/`stored_volatile`). Output reports candidate votes, winning wide rows, and agreement against existing rules on the same winning router. Active learned rules must gain sticky-row provenance/revocation before being enabled.
- `learn-rdns-rules` has a second task, `propose-codes` (after `learn`, same `rdns-rules` limit; CLI `run-rdns-rules -codes [-domains a,b] [-force]`; workflow input `domains` and `force`; skipped with `reject_domains`; plan in
  `docs/rdns-llm-codes-plan.md`). It asks an LLM through OpenRouter (IPv4 only, 180 s timeout, JSON, temperature 0, reasoning low) which part of a domain's PTR names is a city code, for every registered domain with current names
  (5+ hosts one domain per request; 1-4 hosts packed, about 30 per request, one announced country per pack, unknown country alone). **Only patterns are sent, never a name or an IP**: per label, hex runs (6+ characters with a digit, or exactly 7 or 8)
  become `x`, then decimal runs `0` (`hatchet/rdnsrules/llmpatterns.go`; a required unit test checks that no octet survives in any encoding), distinct patterns, top 300 per domain; the real names stay on the VM and test the regex.
  Env (env file only, read in `main.go`): `OPENROUTER_API_KEY` (a secret; absent: `skipped: no key`), `OPENROUTER_MODEL` (default `openai/gpt-6.1-terra`), `OPENROUTER_SECOND_MODEL` (default `openai/gpt-6-luna`); the key never appears in logs, outputs, errors or the table
  (HTTP errors are replaced by fixed texts). A domain is asked when it has no `complete` answer, its newest question is incomplete, a current learned row (ranks 1-3, not withdrawn) has a version missing from the `rule_versions` of its newest complete answer (no wait; an override's new version is recorded), or its pattern set changed and the last complete answer is 30+ days old (`force` always); biggest first, at most 400 requests a run (`stopped: request_cap`),
  fewer when `GET /api/v1/key` shows less credit (about $0.005 a request). An answer is used only after the checks (RE2 regex, one group, anchored, letters-only captures on the real names, 2+ tokens and 20%+ decoded names, small domains: the announced country,
  ISO country, ONE GeoNames place per city by country+region+name or the 10x namesake rule, the learner's domestic gate). GeoNames `cities1000` and `admin1CodesASCII` come from the learner's own monthly cache (`rdnsrules/dictionaries/`).
  An accepted answer is the domain's **rank-4 row** of `public.rdns_city_rules` (`origin = llm`, `dictionary = llm`, `status = candidate`); the learner never reads, writes, retires or deletes rank 4 (`rank <= 3` in its queries), `-reject` withdraws it like every rank,
  and a withdrawn version cannot return. Learned rows are compared per name with rank 4; a disagreement (other country or 100+ km apart) goes to the second model, and when it names the same country within 100 km the learned token gets an `origin = llm` code scoped to its
  extraction (never over a `manual` code; the domestic gate is checked again; effective at once, and kept by the learner). `schema.EnsureRDNSCityRules` widens the rank check to 1-4 only when the old constraint exists.
  `public.rdns_llm_answers` (DDL `schema.EnsureRDNSLLMAnswers`, written only by `learn-rdns-rules`) records every question; only `status = complete` answers count, so an error, a stop or a failed second opinion is asked again next run (verdicts: `accepted`, `rejected`, `no_city`, `blocked`, `error`, and `stopped` for domains a credit stop reached, which are not counted as errors).
  API trouble never fails the task: 403 with `limit_source` key/workspace/guardrail budget and 402 end the run quietly (`stopped: credit_limit`), moderation/other 403 give the domain the verdict `blocked` (a blocked pack is asked again one domain at a time),
  429/5xx/timeouts retry 3 times then count as `error`; only a database error and an invalid key (401, fixed `ErrInvalidKey`) fail the task. The output has counts only.
- `import-mlab` (no cron, started by hand from Hatchet or `run-mlab [-file <path>] [-skip-upload] [-force-upload]`; package `hatchet/mlab/`, tasks `import` → `resolve-names` → `locate` → `upload`, own `mlab` limit; workflow input `file` (a base name in the inbox, no path separator, `.csv` or `.csv.gz`; empty = the newest file there) and `force_upload`) turns the M-Lab traceroute export into the ip2geo layer `36-mlab`.
  M-Lab publishes (CC0) a traceroute from its speed-test server to every client; the owner exports the last 3 hops before each client /24 from BigQuery by hand about monthly (the query and the steps are in the README, "M-Lab export") and copies the CSV (plain or gz) into `/var/lib/openipdata/mlab/inbox/` (owned by `openipdata`). Measured on RIPE Atlas the layer nets about +238 right probes (+1.7 points) at about 41% precision.
  **`import`** streams the CSV as untrusted input: columns found by header (`client24,hop_ip,from_end,traces`; `first_day` optional, only for the day span), strict parsing, public IPv4 only for the /24 (its `.1`) and the hop (`ipdata.PublicV4`), `from_end` 0 to 2, `traces` >= 1 (a value above `maxTraces` = 1,000,000 counts as 1,000,000), a line over 4 KB is bad, at most `maxRows` = 200M lines are read and at least `minValidRows` = 100,000 must be valid (else the non-retryable `ErrPermanent`); bad rows are counted by reason, never echoed. Duplicate (client /24, hop) pairs are merged (smallest `from_end`, traces summed, saturating). Pairs are 12-byte structs sorted in memory (at most `maxPairs` = 40M distinct pairs, about 480 MB, peak near 1.1 GB while the slice grows; 8M pairs took 6 s and 300 MB) and written to `mlab/pairs.csv.gz` (header `client24,hop_ip,from_end,traces`, sorted by /24 then hop, `.tmp` plus rename), which REPLACES the previous file: each import is the full current window.
  **`resolve-names`** looks up the PTR names of the distinct hop IPs with the resolver of `resolve-ips` (`rdns.NameResolver`: system resolver, DoH fallback, 32 workers) into `public.mlab_hop_names` (`ip inet PRIMARY KEY`, `ptr`, `status` ok / not_found / error, `resolved_at`; DDL `schema.EnsureMLab`, `CREATE TABLE IF NOT EXISTS` only, run once at the start of this task; this workflow is the table's only writer). Rows with ok or not_found younger than 60 days are skipped, errors are asked again every run, and an error never replaces an older ok or not_found row. Answers are stored 2000 at a time (a retry or a second run continues where it stopped); a soft budget of 3 hours ends it cleanly (`stopped: time`, `left`; the task timeout is a little above), and `locate` then works with what is there. Rows whose IP is not in the current pairs file and older than 200 days are deleted. A DNS problem never fails the task: only a database error (`rdns.DBError`) and cancellation do.
  **`locate`** is the measured variant "R then M, trace-weighted", per client /24, in two rounds. R: every hop whose `ok` name the production rules decode to a city votes with its `traces` (from_end 0 to 2 count the same); the rules are loaded read-only, no DDL (`rdns.LoadDecoder`: legacy `public.generated_rules` first, then the candidate rules of `public.rdns_city_rules`, a domain's ranks in order, exactly as `locate` of `resolve-ips` decodes a router name; a missing table means no rules). The city (country and normalised name) with the largest weight wins; no winner (no rule city, or a tie) falls to M: every hop with a city in our published ip2geo MMDB votes the same way, but only when the record's `city_source` is in `mmdbStrongSources` (`70-geofeeds`, `60-whois`, `40-hosting`, `50-ix`, `38-asn-geofeed`; never `80-asn-main`, `25-bgp`, `30-pdb`, `35-rdns-wide`, `36-mlab`, `65-rdns`, `67-rdns-names`) and not a hop inside the client /24 itself. Only a city in the client /24's country votes (the country of its `.1` in the MMDB, as in the measurement; a client with no country does not vote), because the layer is `-same-country` and a winner of another country would only be dropped later. A tie in both rounds gives none. The MMDB is this workflow's OWN copy from the private R2 bucket kept in `mlab/` (`rdns.MMDBCopy`, the helper of `locate`/`sample-names`: dated key of today (UTC) else yesterday, ETag, saved copy; an R2 outage uses the saved copy); `mmdbbuilder lookup -db ... -in ... -out ... -with-source -countries` answers for every hop IP and every client `.1`; temp files are removed; no usable MMDB (no R2 setting, no builder, no object, a failed lookup) skips the M round and the country check (`mmdb`, `mmdb_reason`) and R still works. The vote is the pure function `vote` (`hatchet/mlab/locate.go`). It writes `mlab/36-mlab.csv.gz` (the one layer format, source `mlab`, one row per located /24, `.tmp` plus rename); fewer than `minLayerRows` = 1,000 rows fail the task (`ErrPermanent`) without replacing the old file.
  **`upload`** puts the layer at the fixed key `internal/layers/36-mlab.csv.gz` with the sha256 in the object's user metadata (`publish.R2.Put`, `Refresh`; an identical object is not sent again; `force_upload` always sends). No health-check ping.
  Counts only in the outputs, no IP, name or secret in any log line or error (mmdbbuilder's stderr goes through `rdns.ScrubIPs`). `hatchet/mlab` imports `hatchet/rdns` for the thin exports in `rdns/export.go` (`NameResolver`, `Decoder`, `MMDBCopy`, `Connect`, `DBError`, `ScrubIPs`); they add no behaviour to `resolve-ips`.
